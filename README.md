# AquaLine — приложение записи на мойку

Это приложение собрано по промпту «MVP Автосервис от SGX» и настроено под автомойку AquaLine. Один код обслуживает много студий: у каждой свой адрес `/s/<название>/`, своя иконка и свои данные.

- **Клиент** смотрит услуги, цены и фото работ. Он выбирает услугу, день и свободное время и записывается, вводя имя, телефон и машину. Регистрация не нужна. Потом клиент может отменить запись по правилам студии и добавить её в календарь с напоминанием за сутки. Сайт ставится на телефон как приложение.
- **Владелец** входит по почте и паролю. Он видит записи за день и за неделю и итоги: заезды, завершённые работы и полученные деньги. Записи можно принимать, отмечать готовыми, переносить, отменять, отмечать оплату и возврат. Владелец сам меняет услуги, цены, боксы, график, выходные, контакты, логотип, главное фото, три карточки и фото работ.
- **Помощник** отвечает обычным языком на вопросы вроде «Когда ближайшее окно?», «Сколько стоит полировка?», «Что у меня завтра?». Ответы он берёт только из базы студии, через серверные функции.

## Стек

TypeScript, React, Vite, React Router · TanStack Query · Zod · Supabase (база, вход, фото) · date-fns и date-fns-tz · OpenAI SDK на сервере · vite-plugin-pwa и Workbox · Vitest и Playwright · Vercel · pnpm. Иконки: Phosphor.

В промпте ещё были **Astryx Design System** и **liquid-gl**. Их здесь нет: проверить эти пакеты я не смог. Стеклянный эффект сделан своим CSS (`.glass`, размытие и преломление фона в Chrome и Edge, в других браузерах просто матовое стекло). Если пакеты у вас есть, их можно подключить вместо этого CSS.

## Запуск с нуля

1. **Supabase.** Создайте проект. В разделе SQL Editor выполните весь файл `supabase/migrations/0001_init.sql`. Он создаст таблицы, права и хранилище фото.
   - Защиту от двойной записи можно проверить файлом `supabase/tests/double_booking.sql`. Вторая вставка должна упасть.
   - В Authentication → URL Configuration укажите адрес сайта, иначе ссылки из писем будут вести не туда.
2. **Ключи.** Скопируйте `.env.example` в `.env` и заполните.
   - `SUPABASE_SERVICE_ROLE_KEY` и `OPENAI_API_KEY` секретные. Они нужны только серверу и не попадают в браузер.
   - Модель помощника задаётся в `OPENAI_MODEL`, а лимит вопросов в `AI_LIMIT_PER_10_MIN`.
3. **Установка и проверка:**
   ```bash
   pnpm install
   pnpm test          # расчёт свободного времени
   pnpm typecheck
   ```
4. **AquaLine.** Впишите в `tenants/aqualine/tenant.json` почту владельца, адрес и телефон, затем выполните:
   ```bash
   pnpm tenant:check aqualine
   pnpm tenant:publish aqualine          # образец: сайт виден, запись выключена
   ```
   Владельцу придёт письмо, по которому он задаст пароль.
5. **Vercel.** Подключите репозиторий и добавьте те же переменные из `.env` в Settings → Environment Variables. После публикации добавьте `SITE_URL` в `.env`. Если вы используете MCP для Supabase или Vercel, скрипты можно заменить ими. Без них подойдут официальные CLI `supabase` и `vercel`.
6. **Проверка.** Откройте `https://<проект>.vercel.app/s/aqualine/` на телефоне и на компьютере. Если всё в порядке, включите запись:
   ```bash
   pnpm tenant:publish aqualine --live
   ```
7. **E2E-проверка** на отдельной тестовой студии, потому что тест создаёт настоящие записи:
   ```bash
   E2E_URL=https://<проект>.vercel.app E2E_SLUG=test-studio pnpm e2e
   ```

## Новая студия за несколько минут

```bash
pnpm tenant:new detail-pro --name "Detail Pro" --email owner@mail.com
# 1. правим tenants/detail-pro/tenant.json и кладём фото в tenants/detail-pro/photos
pnpm tenant:check detail-pro
pnpm tenant:publish detail-pro           # образец
pnpm tenant:publish detail-pro --live    # после проверки владельцем
```

Ссылка для клиентов: `/s/detail-pro/`, кабинет: `/s/detail-pro/owner`. Исходный код при этом не меняется. После первой публикации услуги, боксы и фото меняет владелец в кабинете. Скрипт их не перезаписывает, пока вы не добавите `--photos`.

## Telegram-бот

Клиент делает всё прямо в чате с ботом. Отдельного приложения ставить не нужно.

- **Запись кнопками.** Клиент выбирает услугу, день и свободное время. Дальше вводит имя (или нажимает «Я — Иван»), телефон (одной кнопкой «Отправить мой номер») и машину, затем подтверждает.
- **«Мои записи».** Клиент видит свои записи и может отменить их по правилам студии.
- **Цены и «Как нас найти»:** адрес, карта, часы работы и телефон.
- **Вопросы обычными словами.** Отвечает тот же помощник, что и на сайте, и только по данным студии.
- **Напоминание за сутки** приходит в Telegram каждый день в 10:00 по Киеву тем, кто придёт завтра.
- **«📱 Открыть приложение»** и кнопка «Записаться» внизу чата открывают сайт прямо в Telegram, с кнопкой «Назад» Telegram. Если записаться там, бот тоже пришлёт напоминание.

Владелец получает в Telegram каждую новую запись с кнопками **«Принять»** и **«Отменить»**, а клиенту сразу приходит ответ. Отмены клиентов тоже приходят владельцу. Команды `/today` и `/tomorrow` показывают записи на сегодня и завтра. Можно спрашивать обычными словами: «Сколько денег получено на этой неделе?»

### Подключение (после того как сайт опубликован на Vercel)

1. В Supabase → SQL Editor выполните `supabase/migrations/0002_telegram.sql`.
2. В Telegram откройте **@BotFather** → `/newbot`. Задайте имя «AquaLine» и адрес, например `aqualine_wash_bot`. Скопируйте токен.
3. Пропишите в `.env` и в Vercel `SITE_URL` (адрес сайта) и `CRON_SECRET` (любая длинная строка).
4. Выполните:
   ```bash
   pnpm tg:setup aqualine --token 123456789:AA...
   ```
   Скрипт сохранит токен на сервере, подключит бота к сайту, настроит меню и кнопку «Записаться». В конце он покажет ссылку на бота и **код владельца**.
5. Владелец пишет боту `/owner <код>`. С этого момента ему приходят уведомления. Так можно подключить несколько человек, например администратора.
6. Ссылку на бота `https://t.me/aqualine_wash_bot` можно ставить в Instagram, на визитки и в Google Maps.

Новой студии подключается свой бот той же командой: `pnpm tg:setup detail-pro --token …`.

**Что проверено:** весь диалог бота прогнан в симуляции (имитация Telegram и базы в памяти). Проверены запись, вторая попытка занять то же время, двойное нажатие «Подтвердить», «Мои записи», отмена, уведомление владельцу, кнопка «Принять» с ответом клиенту, `/today` и `/tomorrow`, вопросы помощнику, керамика на 2 дня, проверка подписи Mini App и напоминание за сутки. С настоящим Telegram бот не проверялся.

## Как устроена надёжность

- **Отдельные данные студий.** Владелец через права в базе (RLS) видит и меняет только свою студию. Клиенты не читают таблицу записей вообще. Занятость они получают через `get_busy`, а там нет ни имён, ни телефонов. Свою запись клиент видит по ключу, который хранится на его устройстве.
- **Запись атомарна.** В базе есть ограничение `no_double_booking`: один бокс нельзя занять дважды на пересекающееся время, считая паузу между машинами. Если двое одновременно выбрали один слот, сохранится только одна запись, а вторая получит другой свободный бокс или сообщение «время только что заняли». Повторное нажатие не создаёт копию: у каждой попытки есть `requestId`.
- **Свободное время** считается одной функцией (`src/lib/schedule.ts`) и в браузере, и на сервере. Она учитывает график, выходные, праздники, число боксов, длительность услуги, паузу между машинами и многодневные работы. Например, керамика на 2 дня закрывает бокс на оба дня.
- **Помощник** получает данные только через серверные функции с проверкой прав. Клиентский помощник не видит чужих записей. Помощник владельца работает только с записями его студии и ничего не меняет. Частота вопросов ограничена.
